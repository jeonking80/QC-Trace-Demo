# 수작업 SQL

`V1/` 아래 파일은 마이그레이션 `StoredProcedures`가 포함 리소스로 읽어 실행합니다.
마이그레이션은 작성 시점 스키마를 고정해야 하므로, 이미 적용된 파일은 고치지 않고 `V2/`에 새 파일을 만들고 새 마이그레이션에서 실행합니다.

- `V1/` → 마이그레이션 `StoredProcedures`: 검사·승인·출하 SP, 앱 역할
- `V5/` → 마이그레이션 `DailySummary`: 일일 검사·출하 집계 뷰(`vw_DailyQcSummary`). 불합격률은 처음 판정 기준(정정 전)
- `V4/` → 마이그레이션 `AdminTools`: 역할 변경 SP(`usp_SetUserRoles`), 재고 대사 뷰(`vw_LotReconciliation`), 앱 계정의 UserRoles·RoleChanges 직접 쓰기 거부
- `V3/` → 마이그레이션 `SpecCheck`: 검사 SP에 R11 규격 검사 추가
- `V2/` → 마이그레이션 `WorkflowProcedures`: LOT 등록, 검사 의뢰, 불합격 처리 SP. 검사 SP는 의뢰 전 LOT을 거절하도록 다시 만든다

**되돌리기(Down) 주의**: `WorkflowProcedures`의 Down은 업무 데이터가 없는 DB에서만 된다. 원장에 Request·Reinspect·Scrap 행이나 Scrapped 수량이 있으면 이전 `CK_Ledger` 제약을 되살릴 수 없어 547 오류로 실패하고 전체가 롤백된다(데이터는 그대로). 원장은 지울 수 없으므로(R3) 이것은 설계상 의도된 제한이다.

## 측정값 JSON (검사 SP `@MeasuredJson`)

`[{"inspectionItemId": 1, "name": "외경", "value": 140.02, "unit": "mm"}, ...]` 형식의 배열입니다.

- 항목은 `inspectionItemId`로 맞추고, 없으면 `name`으로 그 LOT 품목의 검사 항목과 맞춥니다.
- 규격은 요청에 담긴 lower·upper가 아니라 `InspectionItems.Lower~Upper`를 씁니다. 경계값은 규격 안입니다. 측정값은 소수 10자리까지 비교합니다(규격 값은 소수 4자리로 저장).
- 합격(Pass)은 그 품목의 검사 항목 전부에 숫자 측정값이 있어야 합니다(52015). 측정값 생략, `value` null·빈 문자열, 빈 배열, 일부 항목 누락은 모두 거절합니다. 정정으로 합격으로 바꿀 때도 새 측정값 전체가 필요합니다.
- 불합격·보류는 미측정 항목을 허용합니다(그 항목은 판정에 쓰지 않음). 검사 항목이 없는 품목은 측정값 없이 합격할 수 있습니다.
- 이 규칙(2026-11-01 사용자 결정)은 앞으로 들어오는 검사에만 적용됩니다. 이미 적재된 시드 검사 기록은 소급 확인하지 않습니다(시드의 합격 행은 모든 항목에 규격 중앙값이 들어 있습니다).
- 숫자가 아닌 값, 그 품목의 검사 항목이 아닌 값, 배열이 아닌 JSON은 50400입니다.
