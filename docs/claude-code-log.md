# Claude Code 작업 기록

## 진행 방식

- **개발 세션**과 **검증 세션**을 나눴습니다. 개발 세션이 단위를 끝내면 패치와 설명을 넘기고, 검증 세션은 코드를 고치지 않고 실행 결과(테스트, 화면, DB 직접 조회)로만 확인했습니다. 검증 지적을 반영한 뒤 다음 단위로 넘어갔습니다.
- **규칙 테스트(단위 5)** 는 구현 코드를 보지 않는 별도 세션에서 PLAN 3장 규칙 표와 SP 계약서만 보고 작성했습니다. 개발 세션은 그 테스트 코드를 읽지 않고 결과만 받았습니다.
- 커밋은 단위마다 사용자가 결과를 확인한 뒤에만 했습니다.
- 업무 판단이 필요한 문제(아래 "사용자 결정")는 세션이 정하지 않고 사용자에게 물었습니다.

## 불량 유형·폐기 권한 (2026-11-01)

보류했던 품질 개선 3건을 사용자가 정했습니다: 불량 사유는 목록에서 고르고 기타는 직접 입력, 폐기는 관리자만, 비밀번호 변경 화면은 넣지 않음. 검사 기록은 추가 전용이라 이전 자유 입력 사유는 고치지 않고 "유형 없음"으로 집계합니다.

## 검사 일정 협의 (2026-11-01)

사용자가 집 PC에서 LOT 상세를 보며 요청했습니다: 검사자에게 긴급·기한 신호, 부분 검사 뒤 "나머지 언제까지" 회신(사유), 요청자 확인·거절, 결정권자 보고. 결정권자는 관리자와 승인권자 둘 다, 거절하면 바로 결정권자에게 넘기기로 정했습니다. 수량을 바꾸지 않으므로 수량 원장과 따로 `ScheduleEvents`(추가만)에 남기고, 규칙은 SP 4개(의뢰·회신·확인·결정)가 검사합니다. 같은 피드백에서 대시보드 상단 카드를 눌러도 스크롤만 되던 것을 해당 LOT 목록이 열리게 고쳤습니다.

## 집 PC 사용 피드백 (2026-11-01)

테스트는 모두 통과한 상태였지만, 사람이 역할을 바꿔 가며 직접 써 보자 테스트가 보지 않던 문제가 나왔습니다.

- 결함 A2: 합격분을 다 출하하면 불합격이 남아 있어도 LOT이 "출하 완료"가 되어, 검사자 화면(불합격 처리 대기)과 대시보드(출하 완료 LOT 제외)가 서로 다르게 보였습니다. 상태 SP를 고쳐(Data/Sql/V7) 불합격이 남으면 "검사 완료"로 두고, 기존 데이터를 바로잡았습니다.
- 결함 A1: 시드 LOT에 "검사 의뢰" 원장 행이 없었습니다. 시드를 고치고, 기존 DB는 마이그레이션이 보충 행(사유에 "원장 보충" 표시)을 넣습니다.
- 사용성 B1~B6: LOT 상세·조회 화면, 모든 LOT 번호 링크, 생산 담당의 불합격 사유 확인, 검사자 최근 처리 내역, 화면별 단계 안내, 원장 한 줄·한글 표시, 대시보드 불합격 처리 카드와 지표 설명.
- 데모 비밀번호는 사용자 결정으로 `12341234!`(대·소문자 규칙 완화). GitHub Actions는 쓰지 않고 로컬 Docker로만 검증합니다.

## E2E가 찾은 결함 (단위 10)

시나리오 2(불합격 재검사)에서, 전량 불합격된 LOT을 전량 재검사로 되돌리면 상태가 "검사 완료"로 남아 검사 화면 목록에서 사라지는 문제가 나왔습니다. 수량(미검사 20)은 맞았지만 다시 검사할 방법이 없었습니다. 상태 갱신 SP를 고치는 마이그레이션(`ReinspectStatus`, Data/Sql/V6)을 추가하고, 이미 그렇게 남은 LOT을 바로잡았으며, 회귀 테스트 2건을 넣었습니다. SP 단위 테스트와 규칙 테스트는 수량만 보고 상태 전이 후의 화면 동선은 보지 않아서 놓친 경우입니다.
